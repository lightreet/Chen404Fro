# Chen404 前后端代码与文档扫描报告（2026-08-14）

## 1. 扫描目标与结论

本次扫描以 `Chen404Bac`、`Chen404Fro` 的当前源码、配置、数据库迁移、测试和构建结果为事实来源，逐项核对仓库级、后端和前端 Markdown 文档。扫描不包含生产环境登录、线上数据检查和真实第三方服务联调。

结论如下：

- 后端已形成博客内容、知友共创、旅行纪念地图、Sakura Radio、小说书架/阅读器、文件治理、站点配置、管理员消息、GitHub 开发历程和 AI 应用层等完整能力；全量 Maven 验证通过。
- 前端已经覆盖对应公开页、个人中心、创作工作台和管理后台；类型检查、生产构建和 Element Plus 业务边界检查通过。
- 发现 2 个已有前端布局契约测试失败，但 `package.json` 没有统一测试脚本，常规构建无法暴露这组失败。这是本次扫描确认的主要缺陷。
- 生成的 OpenAPI SDK 落后于当前后端接口，现阶段手写 API 封装仍是实际调用入口；SDK 不能被视为完整契约快照。
- 多篇主文档停留在 2026 年 5—7 月的功能状态，尤其在旅行内容可见性、知友创作、音乐播放现场、小说阅读器、管理员消息和开发历程方面与代码不一致。本次已按当前代码统一更新。

## 3. 当前架构事实

### 3.1 后端能力面

| 领域 | 当前实现 |
| --- | --- |
| 认证与用户 | 注册、登录、验证码、JWT 刷新、登出、资料/密码修改、忘记密码、公开用户资料 |
| 内容与互动 | 文章 CRUD、可见性、归档、热门、推荐、上下篇、点赞、收藏、评论、留言、审核 |
| 多用户共创 | `friend-content:view` 与文章/旅行/音乐创作能力；创作能力同时受运行时开关约束 |
| 旅行纪念地图 | 公开/知友可见地点、地点/stop/照片编辑、EXIF、文件引用、旧管理接口兼容 |
| Sakura Radio | 公开曲目/歌单、创作者曲目维护、管理员歌单维护、AI 补全、Redis/本地播放现场 |
| 小说阅读器 | TXT/EPUB/HTML/Markdown/FB2 导入、异步解析、公开/知友/私有可见性、目录、正文、搜索、资源、进度与偏好 |
| 文件 | 多类型上传、受保护文件访问票据、永久化、统一引用、统计、清理与引用重建任务 |
| 站点运营 | 站点配置、运行时功能开关、管理员消息中心、GitHub 开发历程配置与刷新 |
| AI | Lyra 同步/SSE 会话、站内知识检索、文章辅助、音乐补全、相关推荐、后台配置与连接测试 |

### 3.2 前端能力面

- 主站：主页、文章、归档、分类、标签、留言、关于、用户主页和开发历程。
- 身份：登录、注册、忘记密码、短期会话/记住登录、令牌主动刷新和并发刷新收敛。
- 共创：个人中心内统一展示文章、旅行、音乐和知友申请；创作入口按 capability 与运行时开关共同控制。
- 旅行：公开内容直接展示，知友内容按身份扩展；详情以内嵌面板承载，旧详情地址重定向到 `focus` 查询参数。
- 音乐：公开播放、歌单、共享播放器、创作者曲目工作台、管理员歌单与 AI 辅助；登录用户播放现场由后端 Redis 恢复，游客使用本地存储。
- 阅读：公开书架、受控导入、异步状态轮询、目录/正文/搜索、进度和偏好恢复。
- 后台：消息、分类、评论、站点设置、表情、文件、知友申请；站点设置包含开发同步、功能开关和 AI 配置。

| 检查 | 结果 | 说明 |

后端测试编译还产生 `MusicRadioServiceImplTest` 的 unchecked/unsafe operations 警告；它不影响当前构建，但应在后续维护中消除原始类型或不安全转换。

部分 Maven 测试日志中的中文在当前 PowerShell 捕获输出里显示为乱码，但同一源码和文档以 UTF-8 显式读取正常，扫描也未发现替换字符或常见 mojibake 标记；因此将其归类为终端/日志编码显示问题，不作为文件编码损坏。

## 5. 缺陷与风险台账

### 5.1 已确认缺陷

| 编号 | 严重度 | 状态 | 证据与影响 | 建议 |
| --- | --- | --- | --- | --- |
| F-001 | 中 | 待修复 | `node --test src/utils/preciseId.test.ts src/views/Music/Music.layout.test.mjs` 共 9 项，2 项失败。测试期望分页用 `margin-top: auto` 固定在卡片底部，当前为 `margin-top: 0`；测试期望电台面板使用居中等宽双列，当前为 `.95fr/1.05fr` 非对称列。属于布局实现与既有测试契约漂移，是否按测试恢复需结合视觉验收决定。 | 先以当前产品设计确认期望，再同步修改 CSS 或测试；修复后纳入统一测试命令。 |
| F-002 | 中 | 待修复 | `package.json` 未定义 `test`/`test:unit`，因此常规 `npm run build` 和 CI 风格验证不会执行仓库中已有的两个测试文件，导致 F-001 长期隐藏。 | 添加稳定测试脚本，并把它加入前端验证流水线。 |
| F-003 | 中 | 待处理 | `src/sdk/generated` 未包含当前后端的 reader、feature-toggles、notifications、development-history、forgot-password 等接口；手写 API 可正常工作，但生成 SDK 不是完整契约快照。 | 启动当前后端后重新执行 `npm run gen:sdk`，审查生成差异并提交；在此之前不要仅依据生成 SDK 判断接口是否存在。 |
| B-001 | 高 | 2026-08-17 已修复 | GitHub 开发历程把 `per_page=100` 错当成每仓库总抓取上限；两个仓库各抓 100 条后再过滤 Merge，接口恰好只返回 192 条，导致 28 周热力图中的 3—4 月真实提交没有进入响应。 | 已改为以 100 条作为单页大小连续分页直至末页，移除后端/前端/运行时总量配置，并增加 222 条、3 页的回归测试。 |
| D-001 | 低 | 本次已处理 | 主 README 和多篇架构/专题文档仍描述“旅行仅管理员/知友可见”“音乐无断点现场”“小说仅私有”等旧状态。 | 已按当前代码更新现行文档；历史快照保留并加显著说明。 |

2026-08-14 首次扫描没有发现导致后端全量测试或前端生产构建失败的代码缺陷，也没有在未运行真实浏览器、数据库、对象存储和第三方 API 的情况下把潜在联调问题表述为已确认故障。B-001 是 2026-08-17 根据真实页面、Git 历史和分页实现补充确认的联调缺陷；修复后后端 214 个测试、前端生产构建和 Element 边界检查均通过。

### 5.2 结构与性能风险
